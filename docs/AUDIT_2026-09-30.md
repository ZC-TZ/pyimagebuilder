## 覆盖范围

逐段检查 CLI、Registry/Artifactory 下载、CAS 导入与引用、Builder 的 `FROM` 解析、Docker/OCI 归档输出、`load/save/images/rmi`、WSL 参数桥接以及错误恢复。用现有集成测试和离线语义套件复核，并为发现的问题增加回归测试。

## 本轮修复

1. CAS 引用校验补全：核对 layer 描述、manifest 的 config/layer digest、大小和 media type，以及 config 的平台和 diff IDs。损坏引用现在以归档错误失败；`images` 遇到损坏条目会报告错误，不会因缺字段崩溃。
2. gzip 层解压捕获 `zlib.error`，让构建、CAS 导出和下载转换走受控错误路径。
3. WSL 桥接现在能正确转换直接型 CAS base-map 中的仓库路径，保留引用、平台和来源字段。
4. CAS 垃圾回收把仍被镜像引用的未压缩 diff ID blob 视为可达，避免 `cas prune` 删除以后构建会复用的解压层。
5. Artifactory CAS-only 下载在联网前检查所需仓库对象，并显示对应的校验进度说明。

## 第二轮深度复核

6. `load` 的“目标 tar 已相同”快捷路径原先不检查 CAS 引用。现在仍会核对并导入 CAS；发现同标签冲突时要求 `--replace`，避免后续构建与导出读到不同版本。
7. `save` 在多个来源同名时会先生成多个巨大的 tar 再报歧义。现在先判定来源，再只导出选中的镜像；若已有 tar 与 CAS 的 config 不一致，报错提示清理过期 tar。
8. `image prune --dry-run` 原先漏算删除引用后可回收的 CAS blob。现在按候选引用删除后的可达性估算，预览与实际执行使用相同口径；CAS-only 镜像也纳入统计。
9. `repo@sha256:...` 的托管拉取原先把 Registry 的临时 tar 标签误当成仓库引用，导致 `FROM` 无法命中 CAS。现在 CAS 保留原始 digest 引用，Docker save tar 使用稳定的 `:pulled-<12 位摘要>` 标签。Registry 本地模拟覆盖直接 CAS 构建、离线 CLI 构建、保存与刷新。

## 第三轮：Dockerfile 文件树语义

10. `COPY --from=... --exclude=private` 和 `ADD --exclude=private` 解包时，目录条目虽然被排除，其下文件却仍可能进入镜像。统一排除匹配逻辑，使匹配目录及其所有子项同时被过滤；本地 `COPY`、多阶段 `COPY` 和 `ADD` 使用相同判断。
11. 根文件系统索引原先按硬链接的目标**当前路径**读取内容。若后续层覆盖目标路径，硬链接会误读新文件，导致多阶段 `COPY --from` 打包错误。现在应用该层时固定硬链接所指的实际文件成员，并在复制阶段读取该成员。

新增两个完整构建回归样例，分别验证排除目录不会泄漏、覆盖硬链接目标后仍复制原始内容。全量测试更新为 **132 项运行、130 项通过、2 项跳过**；7 个离线兼容样例仍全部通过。真实 Docker 加载、Linux RUN、远端仓库鉴权及 Python 3.7 运行时仍需目标环境验收。

## 第四轮：缓存清理与路径边界

12. `cache prune --older-than ... --dry-run` 原先审计当前引用，因而漏报删除过期条目后才会变成孤儿的层文件。现在预览会排除这些条目后计算孤儿层，并同时报告条目与层的总可回收字节。回归测试覆盖两个条目共享一层、先过期一个再过期两个，以及预览和实际结果一致。
13. 缓存 `entries` / `layers` 与 CAS 内部目录在读写或清理前拒绝符号链接；统一辅助函数也检测 Windows junction，避免沿内部链接操作目录外文件。当前 Windows 账户没有创建符号链接的权限，相关真实链接回归样例自动跳过；其余功能测试通过。

复核 Docker 官方 Dockerfile 参考后确认：`COPY --chown=UID` 未指定组时，GID 等于 UID，原实现正确，本轮未修改。[Dockerfile COPY --chown 规范](https://docs.docker.com/reference/dockerfile/#copy---chown)

全量测试更新为 **134 项运行、131 项通过、3 项跳过**；7 个离线兼容样例通过，75 个 Python 文件通过 Python 3.7 语法解析。交付 zip 的 85 个文件通过 CRC 校验。其中新增跳过项是 Windows 当前账户缺少创建目录符号链接的权限，实际拒绝行为仍需在具备相应权限的环境复核。

## 第五轮：Fast 输入与 Artifactory 下载边界

14. `dist.zip` 同时含有名为 `dist` 的普通文件与 `dist/index.html` 时，旧逻辑在去掉顶层 `dist/` 后会静默丢弃普通文件。其他文件/目录冲突也可能在解压中途才报系统错误。现在先规划并检查整个归档树，冲突直接以构建错误失败，且不会创建解压目标。
15. Artifactory 目录索引中的 `%5C` 在 URL 解码后变为反斜杠，旧检查使用 POSIX 路径语义，Windows 上后续写文件却可能把 `..\` 当作上级目录。现在拒绝反斜杠、驱动器冒号和控制字符，并验证正常 blob 名仍可使用。
16. Fast 以前先解析并拉取基础镜像，之后才检查 `dist.zip`。现在先验证与准备应用包，坏包不会触发基础镜像下载；回归测试直接断言拉取函数未被调用。

全量测试更新为 **136 项运行、133 项通过、3 项跳过**。7 个离线兼容样例通过，75 个 Python 文件通过 Python 3.7 语法解析。真实 nmkf 鉴权、`docker load`、Linux RUN 和 Python 3.7 运行时仍需要目标环境测试。

## 第六轮：SBOM、签名验证和外部归档元数据

17. SBOM 对硬链接原先按其目标的当前路径追踪内容；若后续层覆盖目标路径，SBOM 会把硬链接记成新文件的摘要。现在读取根文件系统索引固定的原始成员。回归测试构建并签名带硬链接的镜像，验证 SBOM 分别记录旧硬链接内容与新目标内容。
18. DSSE 验证器对合法 JSON 但错误类型的 envelope 或 payload 可能抛出未处理异常。现在统一返回可读的 `BuildError`，回归测试覆盖数组 envelope、非字符串 payload 与非法 base64。
19. 外部 Docker save tar 的 manifest/config JSON 原先可不受限地读入内存。镜像读取器、镜像 CLI、Fast 基础 tar 预检和本地镜像缓存的平台检查现统一限制单个 JSON 成员为 16 MiB，超限在解析前失败。测试分别覆盖 manifest 与 config 限额。

全量测试更新为 **138 项运行、135 项通过、3 项跳过**；7 个离线兼容样例通过，76 个 Python 文件通过 Python 3.7 语法解析。本机仍无法代替目标 Linux 与 Docker 环境完成运行时验收。

## 第七轮：独立层缓存和跨层硬链接

20. `COPY/ADD --link` 的独立缓存键原先仅记录原始指令和源内容，漏掉变量展开后的目标路径与权限、当前 WORKDIR 以及 SOURCE_DATE_EPOCH。修改这些输入时可能误用旧层。现在把已展开的 transfer 参数、WORKDIR 和时间戳纳入独立缓存键。回归测试在修复前分别出现错误路径与错误时间戳，修复后通过；无关 ENV 元数据变化仍可命中缓存。
21. 新增硬链接条目在解析目标前就带有 layer/member，导致硬链接链误判为已固定内容。指向下层文件的多级链接可能读取失败，循环链接也可能漏检。现在新链接保持待解析状态，整层索引完成后再固定到真实文件成员。测试覆盖向前引用、跨层目标、目标被后续层覆盖以及循环链接拒绝。

全量测试更新为 **141 项运行、138 项通过、3 项跳过**；7 个离线兼容样例通过，76 个 Python 文件通过 Python 3.7 语法解析。修复通过上述失败样例和既有构建、CAS、Registry、Fast、签名测试共同验证；真实 Docker/Linux/内网环境的验收边界仍与前述相同。

## 第八轮：镜像分析器和优化器输入

22. 镜像分析器按最终路径判断旧文件是否隐藏，未考虑仍有硬链接引用旧内容。旧目标被覆盖后会把实际仍可访问的数据误计为隐藏字节。现在按最终可见文件与硬链接的实际 backing 成员统计；Docker/OCI 两种格式的回归测试覆盖保留链接和 whiteout 删除链接，修复前保留链接的两个样例均失败。
23. 优化器面对 history 中的非对象项、错误类型的 OCI annotations 或 Docker RepoTags 时，原先可能抛出 AttributeError/TypeError。现在在使用前检查元数据类型，返回明确错误。测试同时确认无优化产物遗留。

全量测试更新为 **143 项运行、140 项通过、3 项跳过**；7 个离线兼容样例通过，76 个 Python 文件通过 Python 3.7 语法解析。原有 Docker/OCI 优化后文件树校验、缓存清理、签名及构建测试仍通过。

## 第九轮：下载、缓存与新镜像构建全流程

24. `pull_image` 复用 tar 的分支原先未使用 `locate_archive` 的 CAS 一致性检查；同一镜像引用在 tar 和 CAS 中指向不同 config 时，调用路径不同会返回不同基础镜像。现在两条入口共用检查。回归测试覆盖 local、Registry 和 Artifactory 来源，三个样例在修复前均未拒绝错误 tar。
25. 即便 config 相同，缓存 tar 的 layer 被修改后仍能通过原平台预检。现在已有 CAS 引用时，对 tar 内的层直接流式计算并核对 DiffID，不另写解包文件。修复前篡改层样例未报错，修复后明确失败；CAS 不存在时仍由首次导入执行完整验证。
26. Artifactory 下载遇到探测大小为 0 的文件时，原先因 offset 同为 0 提前返回，却没有创建文件。现在只对实际存在且大小匹配的文件提前返回；新增空文件下载测试。
27. Artifactory 断点续传原先只看 HTTP 206，没有验证 Content-Range 起点和总长度，错误响应会与已有前缀拼成等长的错误数据。现在验证范围、响应体长度和已知总大小；错误范围或截断响应丢弃前缀并重试，统计同步修正。测试覆盖错误起点、合法续传、截断响应、没有预先探测大小的情况；错误起点样例修复前得到 `abcXYZ`，修复后重新取得完整 `ABCDEF`。后续 blob digest 校验仍保留。
28. Registry config 的 rootfs 为数组/null 时原先出现未处理的 AttributeError；无效 DiffID 也会在全部下载后才报错。现在在调度层下载之前检查 rootfs 类型、type=layers、层数量和 DiffID 格式，畸形输入统一返回构建错误，测试确认未请求任何 layer。
29. Registry 拉取已解压并验证的 tar 原先在临时目录清理时丢弃，第一次从 CAS 构建又重新解压。现在在发布 ref 前将已验证的未压缩 tar 按 DiffID 持久化，并保留原压缩 blob；构建直接复用，孤儿清理规则不变。代价是两种表示同时占用磁盘。

新增端到端测试走真实 Registry pull、CAS、基础镜像解析、构建缓存和 Docker archive 导出逻辑，仅用内存模拟 Registry 的网络响应：首次下载后不生成基础 tar；首次构建生成缓存；离线二次构建复用同一条目且不请求网络；远端同名 tag 更新后共享旧基础层，但 COPY 缓存失效；刷新中断后旧 ref 保持可用，仍能离线构建。测试强制禁止 CAS 再次解压，验证第 29 项确实生效，并独立读取输出检查应用包、更新的基础文件、继承 ENV 和 whiteout。

全量测试为 **150 项运行、147 项通过、3 项跳过**；7 个离线兼容样例全部通过，77 个 Python 文件通过 Python 3.7 语法解析。既有 localhost Registry Bearer 鉴权和 Artifactory Basic 鉴权下载、Fast 构建、Docker/OCI 往返测试同时通过。

当前性能边界：Registry 显式刷新仍下载所有层，未实现按已验证 CAS blob 跳过远端下载；CAS 读取仍核对 blob 摘要。不能把存储去重误称为避免网络传输。此次减少的是 Registry 拉取后的重复解压，以及 tar 校验中的额外解包写盘。真实 nmkf/Harbor 鉴权、Docker daemon load、Linux RUN、Python 3.7 实际运行仍需目标环境验收；本机三个符号链接权限相关测试保持跳过。
