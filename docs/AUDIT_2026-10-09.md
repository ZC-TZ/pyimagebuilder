# 2026-10-09：失败路径与缓存归档审计

[文档目录](README.md) · [项目首页](../README.md)

本轮检查远端 ADD、本地缓存 tar 的校验边界，以及镜像输出失败后的文件清理。新增回归测试位于 `tests/test_failure_paths.py`，先运行失败样例确认问题，再修复实现。

## 发现与修复

| 问题 | 修复前的复现结果 | 修复 |
| --- | --- | --- |
| 远端 ADD 未核对响应总长度 | 服务端声明 10 字节，实际只给 4 字节，构建仍成功发布镜像 | 下载结束后核对 Content-Length；将 IncompleteRead 等 HTTPException 转为 BuildError；提前拒绝声明超出上限的响应 |
| 缓存 tar 允许重复成员 | 同名层及 `./` 路径别名重复出现时，缓存复用仍通过 | 按完整读取器相同的 outer_name 规则建立成员索引，遇到重复立即拒绝；查找也使用规范化索引 |
| Windows save 复制失败清理过早 | 输出仍打开时删除残片触发 WinError 32，覆盖原始复制错误，输出文件残留 | 先关闭输入输出句柄，再清理本次创建的输出，保留原始复制异常 |
| pull 导出创建失败可能删除其他写入者的文件 | 预检后、排他创建前出现同名文件时，旧异常处理无条件删除该路径 | save/pull 均记录本次是否成功创建输出；创建失败时不删除已有路径，测试注入创建竞争验证内容保留 |

截断下载测试贯通 builder，确认失败后不发布镜像或缓存条目；还覆盖正确长度、未知长度、过长/过短响应及 IncompleteRead。缓存测试使用正确的重复层内容，确保拒绝的是结构歧义，不是层摘要错误。Windows 清理问题使用真实文件句柄复现。

响应没有 Content-Length 且没有 checksum 时，客户端没有足够信息判断内容是否被完整传输；当前保留允许未知长度下载的行为，不宣称能够检测这种截断。固定远端输入可使用 `ADD --checksum=sha256:...`。

## 新增 rootfs export/import 与保留配置的 flatten

新增独立 rootfs_archive.py，main.py 分派 export/import/flatten。export 合并文件树并输出 rootfs tar，不携带运行配置；import 从 rootfs 新建单层镜像并支持重复 --change；flatten 合并层并默认保留原运行配置。image_changes.py 复用 Dockerfile 解析与变量展开，接受 Docker import 的 11 类元数据指令，WORKDIR/VOLUME 只更新配置，不运行 ONBUILD。独立脚本从其他工作目录运行也使用同一实现。

输入可为本地 Docker/单平台 OCI 归档或现有镜像库引用。CAS 直接提供有序层，不生成中间基础 tar；兼容旧 tar 适配缓存，多个来源明确要求 --source。全程不解包到宿主，应用 whiteout/opaque 后以最终可见 inode 为单位写一层，保留 mode/uid/gid/mtime、符号链接、硬链接关系、FIFO、设备号和 PAX xattr。硬链接目标后来被覆盖时仍引用旧 inode 内容。RootFSIndex 补存特殊文件来源；合并器预读可见头并按偏移读取，在句柄 LRU 淘汰后也不重新扫描整层。

import 接受 tar/gzip/bzip2/xz 或二进制 stdin；export 支持纯二进制 stdout，进度写 stderr。import/flatten 默认 Docker archive，可指定 OCI。新标签支持 registry:port，缺省版本为 latest。输出先在私有目录写入验证，再排他发布，不覆盖已有文件、符号链接或竞争创建的文件。坏路径、重复路径、保留 whiteout 名、链接父目录穿越、硬链接循环/缺失及不支持的类型均拒绝。flatten 是真实派生操作，更新 DiffID/history/config 身份，使用 write_new；原文件/引用不修改，旧签名摘要不适用于新产物。

## 续查：同层路径冲突与运行配置对照漏报

确认并修复两类问题：

| 问题 | 修复前 | 修复后 |
