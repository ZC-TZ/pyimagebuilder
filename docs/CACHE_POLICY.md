# 缓存与镜像复用规则

[文档目录](README.md) · [本地 CAS 镜像库](CAS_STORE.md) · [架构说明](ARCHITECTURE.md)

## 先区分四种数据

| 数据 | 位置 | 命中条件与用途 |
| --- | --- | --- |
| 镜像引用与原始 blob | `cache.imageStore` 下的 `cas/refs`、`cas/blobs/sha256` | 按引用、平台、来源查找；校验 manifest/config 与 blob 摘要，为 FROM 提供基础镜像 |
| 已解码层 | CAS blob 目录中的 DiffID 文件 | 验证传输 blob → DiffID 的对应关系后复用；文件仍需摘要和 tar 结构校验 |
| Docker tar 适配文件与基础层缓存 | 镜像库根目录的 tar；层缓存下的 `base-layers/` | tar 用于兼容导出。显式 tar 的可信基础层缓存绑定归档及层文件身份，失效后重新读取验证 |
| 指令层及 RUN cache mount | 层缓存的 `entries/`、`layers/`、`run-mounts/` | 指令条目复用构建结果；cache mount 为命令提供持久工作目录，两者含义不同 |

`fast.py` 和普通 build 都通过统一镜像解析路径使用 CAS；显式 `baseTar`、`--base-tar` 和 tar 映射继续由归档读取器处理。使用相同配置或路径参数，才能共用同一套运行数据。

## 镜像引用如何选择

- 普通构建优先复用显式导入的 local 镜像，再查所选 Registry/Artifactory 来源。
- 引用、平台、来源分别参与存储键；同名不同平台或不同来源不能互相覆盖。
- `pull` 和 `build --pull` 刷新远端引用；普通 build 复用已有引用。
- `--offline` 不进入下载路径；缺失时明确失败。
- 需要生成 tar 时核对已有 CAS 与 tar 的配置、层内容。内容不一致时报错，不将旧 tar 当成成功的刷新结果。

远端刷新仍验证本次下载的压缩内容与 DiffID，不能因为本地已有同 DiffID 的层就跳过。 CAS 重复入库也验证新输入，即使已有同摘要 blob。该规则覆盖 Registry、OCI、Docker 导入与解码层入库；增加的是重复导入的流式读取，不改普通构建的缓存命中规则。完整规则见 [CAS 镜像库](CAS_STORE.md)。

## 指令缓存键包含什么

| 指令 | 主要输入 |
| --- | --- |
| 普通 COPY/ADD | 父构建状态、指令原文、展开后的源文件指纹 |
| `COPY/ADD --link` | 独立层标识、平台、源指纹、展开后的传输参数、WORKDIR、固定时间戳 |
| 跨阶段 COPY | 源阶段状态，以及当前指令的父状态或独立层输入 |
| WORKDIR/VOLUME | 父状态及指令；父状态包含此前 ARG、ENV、USER 和基础配置 |
| RUN | 父状态、命令、构建参数、实际网络和沙箱模式、架构与模拟执行选项 |

源指纹包含路径、类型、mode、mtime、文件大小、内容、符号链接目标和硬链接关系。本地 COPY/ADD 默认生成 0:0 属主，不把宿主 UID/GID 作为复制结果；跨阶段及 ADD 归档元数据通过来源状态或归档内容参与判断。

父状态包含基础配置、层链、固定 epoch，以及各条指令和结果 DiffID。ARG 的实际值另行计入状态。新结果须先被虚拟 rootfs 及已物化的 RUN 文件系统接受，再发布缓存并报告成功。

本地 COPY/ADD 在缓存未命中并生成新层后，再核对源指纹；发生变化就失败，不把变化后的内容发布到旧键。缓存命中不增加这次二次哈希。构建上下文仍需保持稳定：这是生成前后的核对，不是不可变快照，也不保证检测生成期间改变后又完整恢复的输入。严格封闭构建使用独立的上下文快照流程。

## 验证、升级和中断

当前指令缓存版本为 **24**，可信基础层缓存版本为 **4**。旧指令条目不命中，旧基础层条目重新读取验证；无需联网下载正常镜像或手动清库。CAS schema 仍为 1。

基础层缓存版本4把权限/属主/xattr预检纳入验证凭据，旧条目首次使用重新验证；CAS解码缓存使用时也检查这些声明。

版本 24 兼容基础层中带匹配文件类型位的完整 st_mode（如目录 040755），解析时取有效权限，不改写原始层或 DiffID。ADD 归档先校验来源模式，--chmod 不能掩盖类型冲突；旧指令缓存失效，避免跳过新增的源头检查。已经下载到 CAS 的基础镜像继续复用。

版本 22 同时淘汰旧版误用损坏基础层后生成的后续指令层；仅修复基础层文件不能证明这些后续结果正确。

版本 23 同时淘汰多阶段 RUN 共用物化目录后，根据前一阶段残留文件生成的层及后续结果。
每个阶段第一次实际执行 RUN 时，从该阶段自身的有序镜像层建立独立 rootfs；同一阶段后续 RUN 继续复用该目录并应用新层。
FROM 前一阶段的显式继承、COPY --from 的选定复制保持原语义；层缓存命中不会把其他阶段的物化目录作为当前文件系统。

指令缓存默认检查版本、键、大小与文件身份；身份变化或指定 `--verify-cache` 时重新核对 SHA-256 和完整 tar 结构。

Windows 文件身份额外保存 [FILE_BASIC_INFO.ChangeTime](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_basic_info)，避免创建时间不变、内容修改后恢复 mtime 的误命中；无法读取 ChangeTime 时回退到内容摘要检查。支持该字段的文件系统仍可快速命中，回退路径会增加读取成本。旧 Windows 五字段身份自动重新验证，无需手动清库。

文件身份快速检查只适用于可信本地缓存；不能作为防篡改证明。缓存审计使用同一 tar 结构验证器，不仅检查首个 tar 头。

读取基础 tar 时，把身份绑定到实际打开的归档；读取期间路径或身份变化就失败。可信条目保存初始身份，不能用发布时的新归档身份授权旧数据。身份检查受文件系统时间戳语义和粒度限制，不能证明输入在期间从未被修改；可信基础层缓存要求归档保持稳定。对主动修改并恢复文件属性的场景，使用 `--verify-cache` 重新读取验证。

同一指令缓存键的校验回写与发布使用线程锁和操作系统文件锁；忙时立即报 `Layer cache entry is busy`，待其他操作完成后重试。不同键仍可并发。锁文件保留是正常现象，不代表操作仍在运行；不得手工删除活跃锁文件。

统一镜像库入口的拉取刷新先完成下载、验证及临时目录清理，再替换最终 tar 或删除旧兼容 tar。临时目录清理失败时仍保留旧 tar 与 ref，允许重新尝试；待发布文件会被清理。

镜像引用事务在已有锁内恢复失败或中断前的 ref。CAS 导出和公共复制发布器会清理本次创建的失败文件，避免残缺 tar 阻塞下次离线复用；不会删除其他操作排他创建的同名文件。操作系统强制终止进程、断电或清理本身失败不保证自动恢复，应在重新使用前检查遗留文件。

## 独立入口与产物发布

独立 Registry/Artifactory 下载、CAS 导入导出及构建产物使用同一发布事务规则。
事务覆盖函数内的收尾和工作目录退出；普通异常与 KeyboardInterrupt 都触发恢复。
Registry/Artifactory 的引用锁覆盖下载、发布及恢复，其他同引用写入者可能收到 busy。

- CAS Docker 导入先退出临时目录，再发布 ref。
- CAS ref 替换过程中断时恢复原始快照；load 在调用 CAS 导入前就开始负责失败恢复。
- build/Fast、封闭构建、多平台合并的镜像与附属文件，以及 rootfs 导出、导入、flatten 和优化产物，
  在函数作用域失败时撤销本次已创建的文件；冲突目标未取得所有权，不会登记或删除。
- 主入口的基础映射清理和最终摘要计算也在产物事务内；WSL 启动器只登记成功返回的子进程产物。
- save 和 pull -o 共用交付复制校验：成品逐层核对 DiffID 和 tar 结构，配置原始摘要须与复制前一致。
  普通异常和中断均清理本次副本；失败不会删除缓存源文件。
- 公共文件发布器自身负责处理目标成功创建后、临时副本清理失败的情况。
- 删除某个产物失败时，继续尝试其他产物并恢复 ref；残留文件仍需检查。

ref 快照只保存有大小上限的原始字节，不解析或重编码；因此 --replace 可修复损坏的旧 ref，
失败则原样恢复旧内容。resolve 仍严格解析与校验，不能把损坏快照当成有效镜像使用。

这些是异常恢复规则，不提供对观察者的多文件原子可见性或断电恢复保证。
rootfs 导出的标准输出流也不能撤回已经写出的字节。

## 常用检查与清理

```powershell
# 构建时完整校验缓存层
python .\main.py build -t app:1 -o app.tar --verify-cache .

# 不使用指令层缓存；基础镜像仍可从镜像库复用
python .\main.py build -t app:2 -o app-2.tar --no-cache .

# 检查指令条目及孤儿层
python .\main.py cache ls
python .\main.py cache prune --dry-run
python .\main.py cache prune

# 回收镜像库中无引用的 blob
python .\main.py cas prune --dry-run
python .\main.py cas prune
```

`cache prune` 和 `cas prune` 清理的对象不同。指令缓存的审计和清理先预检所有条目与层节点；空条目、排除项和孤儿层也不能通过链接读取库外文件，伪装成条目或层的目录同样拒绝。过期清理在删除任何旧条目前完成预检。

`image prune` 在按年龄筛选前检查镜像库顶层全部 .tar 节点；伪装成 tar 的目录（包括 junction）会使清理在删除前失败，符号链接继续跳过。
CAS 清理预览的排除项也检查是否为普通文件且不是符号链接；排除只影响可达性计算，不豁免节点检查。

读取与复用同样检查 ref 和兼容 tar 的节点类型：已存在的目录、junction、链接不表示缓存缺失，权限检查失败也不触发来源回退。
默认解析遇到异常本地节点时明确报错，避免静默使用其他来源的同名镜像；真正缺失时仍按既有规则复用其他来源或拉取。

`rmi` 和直接删除 CAS ref 都覆盖删除调用自身的异常恢复，包括 unlink 已生效后抛出的普通异常或 KeyboardInterrupt。
恢复保留引用原始字节，其他来源的引用及共享 blob 不受影响。若兼容 tar 已成功删除后才发生异常，原 CAS 引用会恢复，镜像仍可从 CAS 使用或重新删除；不会重新复制已删除的 tar。

清理前停止相应目录上的构建、拉取、导入及其他写入；条目锁和引用锁不提供全库 GC 与正在使用的层之间的互斥。

RUN 的网络响应和 cache mount 目录内容不会自动使指令缓存失效；更新这些外部内容后需要 `--no-cache` 或改变相应输入。带 secret mount 的 RUN 不读写指令缓存；未固定 checksum 的远程 ADD 同样绕过指令缓存。镜像引用刷新与禁用指令缓存分别由 `--pull`、`--no-cache` 控制。
