# 打包台账与运行数据

[文档目录](../README.md) · [Web 工作台](WEB.md) · [统一配置](CONFIGURATION.md)

成功生成镜像、登记历史和将镜像放入镜像库，是三个不同动作。先按用途选择查询入口：

| 你想知道什么 | 使用入口 |
| --- | --- |
| 本机成功打包过哪些版本 | `main.py builds` / Web“打包台账” |
| 某次 Web 任务的结果与日志 | Web“任务” |
| 哪些镜像可按引用作为 FROM 使用 | `main.py images` / Web“镜像库” |
| tar 文件是否还在、能否加载 | 原输出目录及 `main.py verify 文件.tar` |

## 1. 查询打包版本

以下命令在工具目录执行。Windows 将 `python3` 换成 `python`：

```bash
python3 main.py builds
python3 main.py builds --project hisq
python3 main.py builds --tag hisq_back:1.0.0 --limit 5
python3 main.py builds --json
```

列表按完成时间从新到旧排列，时间为 UTC。`--tag` 精确匹配镜像标签；`--project` 匹配 Fast 保存的项目字段，因此普通 build 记录应按标签查询，或不加项目筛选。

不加 `--project` 会读取同一台账目录中的全部匹配记录。存在多套配置时，用 `--config /data/builder/config.json` 确保构建与查询选择同一路径；它不是每次都必须填写的参数。

## 2. 哪些操作会登记

| 操作 | 是否写打包台账 |
| --- | --- |
| Fast 成功构建 | 是，含项目、版本、包类型与 profile |
| 普通 build 成功构建 | 是，含标签、平台、产物等 |
| Docker/OCI 同时输出 | 一次构建记录，列出两个产物 |
| 构建失败、静态检查 | 否 |
| 加 `--no-build-records` | 否 |
| 仅 pull/load/save/改标签等镜像操作 | 不作为成功应用构建自动补录 |
| 已存在的旧 tar | 不自动追溯登记 |

记录包含输出路径、格式、大小及可用时的 SHA-256，不保存应用包内容、镜像层、仓库密码或完整运行日志。台账写入失败时，构建命令报告错误并撤销本次产物；确实无需台账时可显式禁用登记。

## 3. 数据保存在哪里

| 数据 | 默认或配置位置 | 升级时怎么处理 |
| --- | --- | --- |
| 配置文件 | 自动查找的 `config.json` | 保留自己的文件 |
| 基础镜像库 | 有配置时默认 `<配置目录>/data/image-store/`，由 `cache.imageStore` 覆盖 | 保留，可独立迁移 |
| 指令层缓存 | `cache.layerCache`；未配置时在系统临时目录 | 可保留，不需要随代码更新清空 |
| 成功打包台账 | 默认 `~/.pyimagebuilder/build-records/` | 备份并迁移整个目录 |
| Web 任务摘要 | `<台账目录>/web-jobs/` | 随台账目录备份 |
| 最终 tar / SBOM / 证明 / 签名 | `-o`、profile 的 `outputDir` 或相应输出选项 | 按交付需要保留，台账不代存文件 |
| 浏览器上传的暂存副本 | 工作台使用的系统临时目录 | 任务结束或到期后由工作台清理 |

`~` 表示当前用户主目录，UOS 可能是 `/home/你的账户`，Windows 可能是 `C:/Users/你的账户`。没有配置文件的镜像命令使用系统临时目录中的默认镜像库。默认目录不等于源码目录；以当前配置与环境为准。

台账路径优先级：

1. 环境变量 `PYIMAGEBUILDER_BUILD_RECORDS_DIR`。
2. 配置顶层 `buildRecordsDir`。
3. 当前用户默认目录。

例如，在现有配置顶层加入：

```json
"buildRecordsDir": "./data/build-records"
```

这是 JSON 字段片段，需要放在完整对象中并处理好逗号。相对路径以配置文件所在目录为基准。镜像库、缓存、台账及输出建议放在 Dockerfile 构建上下文之外。

## 4. Web 任务与日志能保留多久

Web 任务摘要保存状态、可复用表单与登记的产物信息；ARG 值、私钥路径和原始日志不写入复用表单或任务摘要。

当前会话日志只保留最近 250 条，重启后不提供旧原始日志。运行失败时应及时导出当前日志；分享前检查其中的命令输出。后台任务在重启后显示为未知状态时，需要核对实际产物和进程，不能当作已完成。

## 5. 找到、校验和迁移产物

移动或删除 tar 不会删除台账记录。记录的是原路径，文件不在时仍能查到曾经构建的版本，但不能从记录恢复镜像。

有登记 SHA-256 的产物可在网页校验并下载；没有摘要的历史条目只显示位置。Web 任务还会单独登记其输出与附属文件，文件仍放在原目录。

程序升级时保留配置、部署 XML、数据目录和交付物。换机器时除了迁移台账，还要迁移实际镜像与输出文件，并调整配置路径；台账中的旧绝对路径不会自动重写。

默认数据位置和字段定义见[配置说明](CONFIGURATION.md#5-缓存与运行数据)，镜像入库与导出见[命令速查](COMMANDS.md#2-查看与管理本地镜像)。
