# Web 工作台

[文档目录](../README.md) · [Fast 打包](FAST.md) · [统一配置](CONFIGURATION.md)

工作台在本机运行，调用同一套 Python 构建和镜像管理命令。适合选择应用包、观察任务进度、下载产物和管理模板；无需另外安装 Web 框架。

## 1. 启动与仓库密码

在工具目录启动：

```bash
python3 main.py --web
```

Windows 使用 `python main.py --web`。配置会自动查找；需要指定时使用 `--config /data/builder/config.json`。默认端口 8765，`--port 0` 自动选择空闲端口。`main.py builds --web` 也可启动。

**仓库密码来自启动进程的环境变量，网页中没有密码输入框。** `repositories.<host>.passwordEnv` 保存变量名，默认 Artifactory 变量为 `PYIMAGEBUILDER_ARTIFACTORY_PASSWORD`。UOS 的 Bash 中可这样输入：

```bash
read -r -s -p '仓库密码: ' PYIMAGEBUILDER_ARTIFACTORY_PASSWORD
echo
export PYIMAGEBUILDER_ARTIFACTORY_PASSWORD
python3 main.py --web
```

`read` 提示输入但不显示密码；`export` 让随后启动的 Python 读取该变量。使用其他变量名时，命令和配置必须一致。修改另一个终端的变量不会改变已启动工作台的环境。

PowerShell 可用隐藏输入：

```powershell
$secret = Read-Host '仓库密码' -AsSecureString
$env:PYIMAGEBUILDER_ARTIFACTORY_PASSWORD = [System.Net.NetworkCredential]::new('', $secret).Password
python main.py --web
```

用本机浏览器打开终端输出的**完整会话链接**。服务只监听回环地址，每次启动生成新链接；不要将会话链接转发给别人。结束时在启动终端按 `Ctrl+C`。

## 2. 页面导航

| 页面 | 用它完成什么 |
| --- | --- |
| 构建 | 快速打包、Dockerfile 构建、静态检查、合并 amd64/arm64 OCI 归档 |
| 任务 | 按状态/关键词查看任务、进度、耗时、日志及结果；复用构建参数 |
| 镜像库 | 搜索标签/平台/来源；拉取、导入、导出、校验、删除与产物操作 |
| 打包台账 | 查询成功构建历史，查看输出位置及可校验下载的产物 |
| 空间 | 区分镜像库、指令缓存与交付 tar；预览并确认受支持的清理 |
| 配置 | 查看运行目录与仓库；新增/编辑 Fast 模板、测试基础镜像、预览配置差异 |

构建页切换模式会保留当前页面表单。镜像库工具按仓库、镜像归档、rootfs 和本地维护分组。完整 CLI 能力仍以[命令速查](COMMANDS.md)及各子命令帮助为准，网页没有覆盖所有高级开关。

## 3. 选择文件与目录

| 方式 | 读取哪里 | 适合什么 |
| --- | --- | --- |
| 输入完整路径 | 运行工作台的机器 | 已存放的 WAR、大型 tar、输出路径 |
| 浏览本机 / 浏览目录 | 运行工作台的机器 | 构建上下文、模板文件、密钥、输出目录 |
| 选择文件 / 拖拽 | 浏览器选择文件，复制到工作台暂存区 | WAR、dist.zip、镜像 tar、Dockerfile 等受支持输入 |

两种浏览方式用途不同：网页的“浏览本机”直接使用原文件路径；系统文件选择器和拖拽会生成临时副本。目录作为 Dockerfile 构建上下文时使用本机路径或目录浏览，不会因为选中了一个 Dockerfile 就自动上传整个项目。

| 暂存对象 | 限制 |
| --- | --- |
| WAR、dist.zip、镜像 tar、rootfs tar | 单文件不超过 2 GiB |
| Dockerfile | 不超过 1 MiB |
| 当前工作台暂存 | 最多 24 个文件，总配额 4 GiB |
| 未提交的暂存文件 | 空闲 30 分钟后由工作台回收 |

多架构合并的两个输入在提交前检查平台。暂存文件在任务结束后清理；清理失败保留配额并重试。被替换的目录、文件及后来放入的其他文件不会递归删除。细节见[资源生命周期](../CONCURRENCY_AND_RESOURCES.md)。

## 4. 提交一次打包或构建

**快速打包：**

1. 选择 WAR 或 dist.zip，填写项目和版本。
2. 选择已配置好的 `tongweb` 或 `tomcat` 模板，核对目标平台。
3. 查看预览中的镜像标签、部署目录和输出位置，提交任务。
4. 在任务详情查看结果，成功后校验并下载 tar。

Fast 默认使用模板的 `outputDir`。未配置输出目录时，手输应用包路径可输出到包所在目录；上传/拖拽文件需要填写输出 tar 路径。输出必须是尚不存在的新文件。

**Dockerfile 构建：**填写本机上下文目录，按需选择 Dockerfile、基础 tar 或基础镜像映射，设置标签与输出。可先做静态检查；高级区域包含 ARG、目标阶段、固定时间戳、输入锁、SBOM 与签名。Linux 页面可允许执行可信 Dockerfile 的 RUN；Windows Web 不提供 WSL RUN 转接，需使用 [CLI 的 WSL 方式](ADVANCED.md#执行-run)。

**合并 OCI：**分别选择已有 amd64 和 arm64 的单平台 OCI tar，再填写合并标签与输出。合并不负责构建缺少的架构。

## 5. 进度、日志和取消

同一工作台按提交顺序执行任务。任务详情增量更新日志，不会整页刷新：

- 默认跟随最新日志；向上滚动暂停，点击“跳到最新”或滚回底部恢复。
- 日志区有行号、相对时间和阶段/完成/缓存/失败配色。
- 有 Artifactory CAS 拉取快照时，单独显示元数据、并行下载、完成层准备、入库提交、镜像就绪五阶段。
- 层编号表示 manifest 中的位置；“已完成”是实际完成数，并发时编号可以乱序。
- 网络下载完成后仍可能在解压、校验或入库；基础镜像就绪也不代表应用构建完成。

原始日志只在当前会话保留最近 **250 条**；更早的行会移出窗口。“导出当前日志”导出当前保留部分的 UTF-8 纯文本，不含界面行号和配色。需要保存完整 CLI 日志时见[性能排查](PERFORMANCE.md#2-怎样看日志)，事件格式见[进度输出参考](../PROGRESS.md)。

排队任务可取消；Linux 上也可请求取消运行中任务。Windows 停止工作台时等待运行任务收尾。真实 Linux RUN 的取消与权限仍需目标环境验收。

## 6. 结果、历史和产物

| 内容 | 重启后是否保留 |
| --- | --- |
| 成功打包台账 | 保留，在台账目录 |
| Web 任务结果、可复用表单、已登记产物记录 | 保留，在台账目录的 `web-jobs/` |
| 当前会话原始日志、上传副本 | 不作为持久历史保存；暂存清理由工作台负责 |
| 仓库密码 | 从启动环境读取，不写入任务摘要 |
| 输出 tar、SBOM、证明及签名文件 | 仍位于原输出目录，不会复制进台账 |

任务复用不会保存 ARG 的实际值和签名私钥路径；需要重新填写。使用过暂存包或 Dockerfile 时需要重新选择文件。重启前仍在运行的旧任务不能据历史摘要判定成功。

可下载的登记产物在发送前会验证摘要；下载结束或断开后释放临时副本。需要预留临时空间。移动或删除 tar 后，历史记录仍保留原位置。详见[打包台账](HISTORY.md)。

## 7. 镜像库与产物操作

| 来源 | 可用操作 |
| --- | --- |
| Docker tar | 校验、导入、改标签另存、推送、rootfs 导出、层历史、分析、优化、扁平化、裁剪与压缩、仅压缩归档 |
| 有登记摘要的单平台 OCI tar | 校验、导入 CAS、推送、rootfs 导出、层历史、分析、优化、扁平化、裁剪与压缩、仅压缩归档 |
| 镜像库中仅有 CAS 数据 | 核对引用/blob、导出 Docker tar/rootfs、历史、分析、优化、扁平化、裁剪与压缩 |
| 多架构合并任务的 OCI tar | 从任务结果校验、推送或仅压缩多架构镜像 |

从台账或镜像库进入“产物操作”时会带入来源、标签和平台。历史产物以登记摘要验证私有副本；CAS 标签在提交前发生变化时需要重新选择。

推送只接受配置中已有的 Registry/Harbor 和显式标签。先预览，再确认；确认只能使用一次，已有远端标签时拒绝推送，网页不提供覆盖开关。

rootfs 导入从空运行配置开始；希望保留原启动配置时使用“扁平化并另存”。签名产物可进入“校验交付签名”，提供可信公钥及签名覆盖的归档、SBOM 和证明文件。

**仅压缩归档：**从已有 tar 的产物操作进入，设置新 `.tar.gz` / `.tgz` 路径和级别。保留全部 tar 字节与镜像身份，下载压缩包及 `.compress.json`；仅 CAS 数据需先导出。与 slim 的区别和校验边界见[仅压缩 tar](COMPRESSION.md)。

**裁剪与压缩镜像：**从产物操作进入，填写删除/保护规则和新输出路径。默认仅预览，先下载完整 `.slim.json` 审计报告；核对后取消预览，再提交生成新 Docker tar。可选 gzip、1–9 压缩级别及未压缩大小阈值；任务结果分别下载归档和报告。没有删除规则时只扁平化，内置保护无法替代应用验收。完整语义见[镜像裁剪与压缩](SLIM.md)。

## 8. 配置、诊断与清理

Fast 模板在网页预览差异、保存后即生效。测试本地基础 tar 会核对层；Artifactory 模板测试只检查远端 manifest/config，不下载全部层。

仓库地址、账户、密码变量名、协议和 CA 在配置文件中维护；手工编辑后重启工作台。仓库诊断可检查 API，填写完整镜像引用还可检查标签及读取权限，不能据此证明推送权限。HTTP/HTTPS 与证书设置见[配置说明](CONFIGURATION.md#3-下载地址与鉴权)。

空间页将旧镜像、构建缓存和交付 tar 分开。镜像删除会重新核对勾选引用；过期缓存清理确认会重新比对候选并检查维护条件。共享层、硬链接和压缩会影响实际释放空间。更多清理方式见[排错指南](TROUBLESHOOTING.md#怎么安全清理)。

## 9. 更新工作台

停止旧工作台后更新代码，保留 `config.json`、部署 XML、镜像库、层缓存、台账和输出目录，再启动并打开新的会话链接。正在运行的旧进程不会自动使用新代码。
